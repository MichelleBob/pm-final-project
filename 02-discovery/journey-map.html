Future state journey: debtor with variable income

Pilot in DE, one segment. A transparent digital instalment plan that consumers can keep, with the Self-Service Rate (SSR) safeguarded by quality metrics (missed payments, agent contacts).

Persona: A debtor with variable income and multiple claims who is looking for a quick answer.

Goal: Find out whether and how they can pay in instalments without committing long-term to something they can't sustain.

Value proposition: A transparent, guided repayment journey that helps consumers choose sustainable instalment plans the first time, reducing unnecessary agent interactions and improving long-term recovery beyond SSR.

The four stages (Action → Benefit)

  1. Get answer
    • User action: Opens link, sees instalment yes/no first → the ten-minute question is answered instantly.
    • Internal state: Groups both claims and shows how they relate → no confusion about paying one claim.
    • Pain point addressed: Leads with the answer, not case data → removes the wall-of-numbers moment (P1, P2).
  2. Show range
    • User action: Enters best and worst month income → expresses the truth without picking one false number.
    • Internal state: Calculates the plan within the stated range, no preset value → removes anchoring on 150 euros.
    • Pain point addressed: Slider default and missing variable-income input → addresses P3 and P4 (High).
  3. Know rules
    • User action: Sees what a missed payment triggers → fear of total acceleration drops before committing.
    • Internal state: Stress-tests plan against worst month, explains income use → lowers under-reporting.
    • Pain point addressed: Acceleration fear and unexplained income request → addresses P7 (Critical), P5, P8.
  4. Stay on plan
    • User action: Confirms plan, picks start date near payday → no exit over timing (P9).
    • Internal state: Logs inputs, offer shown and rationale for agents → no repeated data collection.
    • Pain point addressed: Empty agent cases and silent over-commitment → closes the agent-handoff Critical and theme 7.

Pilot guardrail: Track 60-day missed payments and agent contacts next to SSR, so a rising SSR cannot hide failing plans.

Competitive advantages over the manual workaround

1. In-journey reassuranceReplaces the reassurance call (P10) → fewer agent contacts, no waiting time.
2. Range-based inputRemoves the reason to under-report (P8) → plans rest on true income.
3. Logged inputs and rationaleAgents continue instead of restarting → plans survive past sign-up.

Risks and open points

SSR may dip in the pilot. Showing consequences and a worst-month range will lose some sign-ups that succeed today through silent over-commitment. Stakeholders need to hear this before the numbers come in.

Stage 3 needs Legal. The copy on what a missed payment triggers must match actual contract and acceleration terms. If the real answer is full acceleration, transparency may raise abandonment. That is a policy question, not a design one.

Stage 2 logic is an assumption. How plan size is derived from a best/worst range is not in the research and must be defined with the business side.
